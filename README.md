# 무붕 공간 · Netlify 배포판

무붕의 합주실 예약·멤버와 팀 등록·공지·위키 사이트입니다. 구글 캘린더 연결 없이 로컬에서는 SQLite, 공개 배포에서는 Supabase PostgreSQL에 저장합니다. 제공받은 검정·크롬 로고를 적용했습니다.

## 시작하기

Mac에서는 `start.command`를 실행하고 `http://127.0.0.1:4318`을 엽니다. 첫 실행에 운영진 계정을 만든 뒤 **멤버·팀 관리 → 엑셀 양식 다운로드 → 파일 검토 → 일괄 등록**을 이용합니다. 기존 서비스의 계정·예약은 자동 이전되지 않습니다.

`start.command`는 브라우저를 자동으로 엽니다. 이미 무붕 서버가 켜져 있으면 새 서버를 만들지 않고 기존 사이트를 엽니다. `EADDRINUSE`는 포트가 사용 중이라는 뜻으로, 기존 버전을 실행했다면 위 주소에 바로 접속하세요. 서버를 처음 켠 터미널에서 Ctrl+C를 누르면 종료됩니다.

Node.js 24 이상이 필요합니다. 먼저 `npm ci`로 패키지를 설치한 뒤 로컬에서는 `node server.mjs`로 실행합니다. 사이트 실행에는 Python이 필요하지 않습니다. Python 3은 이전 파일 파서와의 호환성 테스트에만 사용합니다. `PORT`, `DATA_DIR` 환경변수를 지원합니다. 공개 배포는 [NETLIFY-START.md](NETLIFY-START.md)를 순서대로 따라 하세요.

## 엑셀 양식 (기존 파일 유지)

- 멤버: **아이디, 이름, 비밀번호, 세션, 기수, 전화번호, 팀, 관리자여부**
- 팀: **팀명, 보컬, 기타1, 기타2, 베이스, 드럼, 키보드**
- 신규 아이디 빈칸은 이름, 신규 비밀번호 빈칸은 `20000000`입니다. 처음 로그인할 때 비밀번호를 변경합니다. 기존 멤버의 빈 비밀번호는 현재 비밀번호를 유지합니다.
- 멤버 시트의 **팀은 빈칸**으로 둡니다. 팀 시트 각 파트에 멤버 아이디를 입력하면 해당 멤버의 팀 목록이 자동으로 채워집니다. 다른 팀으로 옮기거나 공석으로 바꾸면 소속도 자동 갱신됩니다. 여러 팀·파트 겸임을 지원합니다.
- 팀은 팀명, 멤버는 아이디로 기존/신규를 구분합니다. 동명이인은 아이디를 다르게 입력하세요. 전화번호는 텍스트로 입력해 앞의 0을 보존하세요.
- 팀의 공석은 빈칸입니다. 기존 팀 행의 빈칸은 해당 자리를 비웁니다. 파일에 없는 기존 멤버·팀은 자동 삭제하지 않습니다.
- 기존 멤버의 빈 관리자여부는 권한 유지, 신규는 일반부원입니다. Y/N으로 권한을 지정합니다. 현재 운영진 본인의 권한 해제는 막습니다. 다른 일반 정보의 빈칸은 그 정보를 비웁니다.
- 검토 화면에 소속 팀 변경, 권한 변경, 오류가 표시됩니다. 검토는 15분 후 만료됩니다. `.xlsx` 4MB 이하, 시트별 1,000행까지, 수식 셀은 지원하지 않습니다. Netlify에서는 실행 시간 제한 때문에 신규 등록·비밀번호 설정을 합쳐 한 번에 최대 100명까지 처리합니다. 기존 멤버의 비밀번호 칸을 비우면 1,000명까지 일반 정보를 수정할 수 있습니다.

## 예약

- 운영진은 **커스텀 일정**에서 대청소·면접 등의 제목·설명·날짜·시간을 등록합니다. 일반부원에게도 주간표에 표시하지만 등록·수정·삭제는 운영진만 가능합니다. 해당 시간의 예약을 막고 개인·팀 시간 한도에는 포함하지 않습니다. 최대 1년 뒤까지 날짜별로 등록하며, 08:00–24:00을 선택해 하루 전체를 막을 수 있습니다. 기존 예약·일정과 겹치면 저장하지 않습니다.

- 한국 시간 **08:00–24:00**, 30분 단위. 모바일에서도 7일 주간표를 보고 예약합니다. ‘넓게 보기’로 가로 스크롤할 수 있고 예약 창 안에도 주간표가 표시됩니다.
- 기본 한도는 개인 주 3시간, 팀 주 6시간, 연속 3시간, 4주 앞까지입니다. 운영진이 조정할 수 있습니다. 예약 화면에 팀별 사용 시간과 한도를 표시합니다.
- 팀 합주는 해당 팀 소속 멤버가 예약합니다. 운영진은 모든 팀을 선택할 수 있고, 개인 연습에서는 모든 멤버를 선택해 대신 예약할 수 있습니다. 예약 대상 멤버·팀의 시간 한도와 중복 방지 규칙을 적용합니다. 팀 목록은 이름순, 멤버 목록은 이름·기수·세션 기준 오름/내림차순으로 정렬합니다.
- 팀 예약에서 ‘매주 반복’을 선택하고 마지막 날짜를 지정하면 해당 날짜까지(포함) 같은 요일·시간에 등록됩니다. 첫 날짜는 예약 가능 기간 안이어야 하며 반복 종료는 최대 1년입니다. 운영진의 정기예약 마감일도 적용합니다.
- 반복 중 한 날짜라도 충돌하거나 한도를 넘으면 **전체 등록을 취소**합니다. 반복 예약은 한 회만 취소하거나 같은 반복 묶음 전체를 취소할 수 있습니다. 전체 취소 전 날짜·건수를 표시합니다. 운영진의 전체 취소는 지난 날짜도 포함하고, 일반부원은 전체 날짜에 취소 권한이 있어야 합니다.
- 일반부원은 시작 전의 본인·소속 팀 예약을 취소합니다. ‘일반 부원의 당일 취소 제한’을 켜면 한국 날짜 기준 당일에는 운영진만 취소합니다. 운영진은 전체 예약을 취소할 수 있습니다.

## 공지·무붕 위키

운영진이 작성·수정·상단 고정하며 로그인한 부원이 읽습니다. 부원 사용법 공지를 최초 1회 자동 등록하고, 관리 메뉴에 운영진 사용법을 제공합니다. 기존 게시물은 덮어쓰지 않습니다.

본문의 http/https 주소는 클릭 가능한 링크가 됩니다. 공지와 위키에 파일당 10MB, 게시물당 5개까지 PDF·이미지·문서·엑셀·ZIP을 첨부할 수 있습니다.

**노션 가져오기:** 노션에서 HTML 형식으로 내보낸 뒤 위키의 ‘노션 가져오기’에 `.html` 또는 `.zip`을 올립니다. 이미지를 포함하려면 내보낸 ZIP을 그대로 올리세요. 여러 페이지가 있으면 가져올 페이지를 선택합니다. 제목·본문·표·목록·이미지와 지원되는 서식을 보존하는 복사본입니다. 노션의 실시간 동기화, 데이터베이스 기능, 임베드 앱, 하위 페이지 간 연결은 재현하지 않습니다. 하위 페이지는 각각 가져오세요. 원본을 계속 보려면 위키 문서의 ‘노션·원문 주소’를 등록합니다.

## 화면 갱신·로그아웃·예약자 표시

화면 오른쪽 위에 운영진·일반부원 공통 로그아웃 버튼이 있습니다. 재방문 메뉴는 메모리에 보관한 화면을 먼저 보여주고 서버의 최신 내용으로 갱신합니다. 로그아웃과 정보 수정 후에는 캐시를 비웁니다. 멤버·팀·예약·공지 목록의 반복 DB 조회를 줄였습니다.

시간표와 예약 상세에 실제 등록한 사람을 표시합니다. 운영진의 대리 예약은 이용 멤버와 등록자를 구분해 저장합니다. 이전 예약처럼 등록자 정보가 따로 없는 기록은 기존 예약자 정보를 사용합니다. `created_by` 열과 조회용 인덱스는 서버 재시작 시 자동 추가합니다.

## 운영진 비밀번호 관리

멤버 목록의 **재설정**에서 임시 비밀번호를 직접 입력하거나 자동 생성합니다. 보기·복사 버튼을 제공하며 저장 시 운영진 본인의 현재 비밀번호를 확인합니다. 대상 멤버의 기존 로그인을 모두 해제하고 다음 로그인에서 변경하도록 합니다. 기존 비밀번호는 해시만 저장하므로 조회할 수 없습니다. 임시 비밀번호는 저장 완료 창을 닫으면 재조회할 수 없습니다. 운영진 본인의 행에는 **내 비밀번호 변경**이 표시됩니다. 엑셀 양식은 변경하지 않았습니다.

## 저장·백업

운영진은 **멤버·팀 관리 → 전체 멤버 내려받기**로 현재 전체 명단과 팀 구성을 `.xlsx`로 저장할 수 있습니다. 기존 열 순서와 양식을 유지하고 이름·기수·세션 정렬 방향을 적용합니다. 검색어로 명단을 줄이지는 않습니다. 전화번호의 앞자리 0을 유지하며 비밀번호는 빈칸입니다. 재등록하면 기존 멤버의 빈 비밀번호는 유지되고 소속 팀은 팀 시트에서 갱신됩니다. 이 엑셀은 명단용이며 비밀번호·예약·게시물까지 복구하는 전체 백업은 아닙니다. 전체 백업은 `transfer-data.mjs`를 사용하며 커스텀 일정도 포함됩니다.

공개 배포는 `netlify.toml`을 이용해 Netlify Free에 올리고 Supabase pooler 연결 주소를 `DATABASE_URL`로 입력합니다. 서버리스에서는 Transaction pooler(6543)를 권장하며 기존 Session pooler(5432)도 지원합니다. 멤버·예약·첨부파일·위키 이미지는 모두 Supabase DB에 저장합니다. 실제 운영 데이터는 이 배포 파일에 포함되지 않습니다. 배포·이전·백업의 순서는 [DEPLOYMENT.md](DEPLOYMENT.md)에 있습니다.

로컬 기본 DB는 `data/mooboong.sqlite`입니다. 로컬에서는 `node backup.mjs`, PostgreSQL에서는 `node --env-file=.env transfer-data.mjs export 날짜.backup.json`을 사용합니다. 복구는 빈 PostgreSQL DB에만 허용됩니다.

## 검증

`npm ci` 후 `node --test tests/*.test.mjs`와 `python3 -m unittest discover -s tests -p '*_test.py'`로 인증, 엑셀 등록/팀 자동 소속, 예약 충돌·반복 원자성·시간 한도, 당일 취소 정책, 공지/첨부 권한, HTML 가져오기 안전 처리를 검사합니다.

공개 운영은 Netlify 배포 주소 또는 연결한 도메인으로 접속합니다. 로컬 주소는 다른 사람에게 공유해도 접속할 수 없습니다. 아이콘 라이선스는 `LICENSES.md`에 있습니다.

## Netlify 구현과 제한

화면은 CDN에서 제공하고 `/api/*`만 Functions에서 처리합니다. DB 연결은 실행 환경당 최대 2개이며 Transaction pooler는 스키마를 명시한 쿼리로 사용합니다. 여러 함수 인스턴스가 같은 세션·암호화된 임시 파일·로그인 시도 제한을 공유합니다. 모든 예약 생성은 PostgreSQL 트랜잭션 잠금을 사용하며 반복 예약은 한 번에 저장합니다.

큰 업로드는 1MB씩 나누어 전송합니다. 첨부파일은 기존 10MB, 노션 ZIP 입력은 기존 20MB까지입니다. 이미지가 내장된 최종 노션 HTML은 18MB까지이며 더 큰 문서는 나누어 가져오세요. 기존 DB에 이미 저장된 19MB 초과 HTML 문서는 Netlify에서 열 수 없으므로 전환 전에 나누어 다시 가져와야 합니다. 임시 파일은 15분 후 만료되며 다음 API 정리 작업에서 삭제됩니다. DB 백업에는 임시 파일·로그인 제한 카운터를 넣지 않습니다.

Netlify 무료 함수의 실행 지역은 기본 미국이므로 Supabase 지역에 따른 조회 지연은 배포 후 확인해야 합니다. 실행 제한은 60초이며 신규/비밀번호 설정 멤버 100명 제한은 이 때문에 적용합니다. 무료 사용량을 초과하면 사이트가 일시 중단될 수 있습니다.
